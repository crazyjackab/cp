# File Manager — 功能与 UI 优化建议

> 基于 v0.2.x 代码库与界面通读整理（2026-05-31）。  
> 侧重**用户可感知的功能体验**与**界面/交互设计**，与 [功能规划建议.md](./功能规划建议.md)（路线图）、[代码审视与优化建议.md](./代码审视与优化建议.md)（工程实现）互补。

---

## 一、审视范围与总体评价

### 1.1 审视范围

| 维度 | 覆盖内容 |
| ---- | -------- |
| 信息架构 | 侧栏导航、资料库分类、工具页（总览/查重/日志/设置） |
| 核心流程 | 收纳、浏览、搜索筛选、预览、批量操作、还原/删除 |
| 视觉与主题 | 深色/浅色/跟随系统、强调色、字号、组件一致性 |
| 交互细节 | 拖拽、多选、进度反馈、空状态、通知与 toast |
| 产品缺口 | 与 [产品设计.md](./产品设计.md) 对比尚未闭环的能力 |

### 1.2 总体评价

当前版本已具备较完整的「私人资料库」主链路：**收纳 → 分类存放 → 浏览/搜索/预览 → 批量整理 → 日志追溯**。后台任务、托盘、智能提醒、虚拟列表等基础设施成熟，整体 UI 风格统一（Segoe UI + 暗色默认 + 卡片/面板布局）。

主要提升空间在于：

1. **信息密度与导航**：侧栏缺少数量提示，子文件夹无面包屑，「全部」与单分类之间上下文切换成本偏高。
2. **操作效率**：文件行操作按钮过多（8 个 icon），无右键菜单与全局快捷键；预览弹窗已支持连续浏览，仍缺 Space 快捷预览等。
3. **产品闭环**：收件箱仅有目录、无工作流；总览扫描与收纳/查重未打通；部分设置项（开机自启等）后端能力未暴露到 UI。
4. **首次与日常引导**：空状态文案较好，但缺少「打开即知该做什么」的首页/dashboard。

## 二、UI / UX 优化建议

以下按**用户感知强度 × 实现成本**排序，标注难度：**低 / 中 / 高**。

### 2.1 导航与信息架构

#### 2.1.1 侧栏显示分类文件数与占用（低）

**现状**：`get_library_info()` 已返回各分类 `file_count` / `bytes`，但 `SidebarLibraryNav` 仅展示分类名称，用户无法一眼判断「图片有多少」「收件箱是否待处理」。

**建议**：

- 在「图片」「视频」「文档」等条目右侧显示文件数 badge；超过 99 显示 `99+`。
- 「收件箱」有未处理文件时用强调色或圆点提示（与智能提醒阈值联动更佳）。
- 可选：hover 时 tooltip 显示占用空间。

**价值**：减少无意义点进空分类；强化「收件箱待整理」心智。

---

#### 2.1.2 子文件夹面包屑（低～中）

**现状**：进入子文件夹后，`LibraryToolbar` 标题显示文件夹名，`page-subtitle` 显示完整路径，但缺少可点击的层级导航；返回上级需依赖侧栏树展开。

**建议**：

- 在 `page-header` 下方或标题区增加面包屑：`全部 > 图片 > 2024旅行 > …`
- 每一级可点击跳转；最后一级为当前文件夹名（不可点）。
- 与侧栏 `expandedFolderPaths` 状态同步，点击面包屑时自动展开对应树节点。

**价值**：深层目录浏览时显著降低「迷路感」。

---

#### 2.1.3 侧栏分类分组与折叠（低）

**现状**：侧栏 10 个资料库入口（全部、收藏、8 个分类）+ 4 个工具入口，纵向较长；「压缩包」「安装包」「其他」使用频率通常低于「图片/视频/文档」。

**建议**：

- 将分类分为 **常用**（图片、视频、文档、音频、收件箱）与 **其他**（压缩包、安装包、其他），后者默认折叠。
- 或在设置中允许用户自定义侧栏可见分类（长期）。

---

#### 2.1.4 资料库「首页 / 仪表盘」（中）

**现状**：默认进入「全部文件」列表；若资料库为空则显示收纳引导，有文件时直接进入列表，缺少全局概览。

**建议**：新增可选「首页」或在「全部」顶部增加 dashboard 区块：

| 模块 | 内容 |
| ---- | ---- |
| 概览卡片 | 总文件数、总占用、今日/本周新增（来自 import_log） |
| 分类占比 | 简易条形图或卡片（复用 `LibraryInfo.categories`） |
| 快捷操作 | 收纳桌面/下载、打开收件箱、查看最近收纳 |
| 提醒 | 桌面/下载超阈值、错放分类数量、可用更新 |

**价值**：打开软件即获得「资料库健康度」，符合产品设计里「打开软件 → 直接看到自己的资料库」的目标。

---

### 2.2 布局与视觉

#### 2.2.1 顶栏操作区收敛（低～中）

**现状**：`LibraryToolbar` 同时放置「收纳文件」「新建文件夹」「桌面」「下载」「错放整理」「刷新」共 6 个按钮，窄窗口下易换行或溢出。

**建议**：

- 主按钮保留：**收纳文件**（primary）。
- 「桌面」「下载」收入 **「快速收纳 ▾」** 下拉或 split button。
- 「错放整理」仅在检测到 `misplacedCount > 0` 或当前为「全部/某分类」时显示；无问题时收进「更多 ⋯」菜单。
- 「新建文件夹」可移至列表区空状态或右键菜单，减少顶栏常驻项。

---

#### 2.2.2 文件行操作改为「主操作 + 更多」（中）

**现状**：`LibraryFileRow` 右侧固定 8 个 icon 按钮（收藏、标签、预览、打开、定位、还原、重命名、删除），行宽大时信息区被挤压，窄窗口下操作区换行混乱。

**建议**：

- **常驻**：收藏、打开（或预览）、「⋯ 更多」。
- **更多菜单 / 右键菜单**：定位、还原、重命名、删除、编辑标签。
- 列表 hover 时才显示操作区（已有 `selection-active` 模式，可统一为 hover-reveal）。
- 危险操作「删除」在菜单内保持红色，避免误触。

**价值**：界面更干净，与 Windows 资源管理器「右键」习惯一致（见 §2.3.2）。

---

#### 2.2.3 搜索筛选区可折叠（低）✅ 已完成

**现状**：`LibrarySearchBar` 含搜索框、时间/大小下拉、扩展名 chips、标签 chips；扩展名种类多时占用大量垂直空间，挤压文件列表可视区域。

**建议**：

- 默认只显示搜索框 + 「筛选 ▾」按钮 + 已激活筛选的摘要 chips。
- 点击「筛选」展开高级面板（时间、大小、扩展名、标签）。
- 切换分类时：可选「记住上次筛选」或「仅重置扩展名/标签、保留搜索词」（见 §3.2.2）。

**完成说明（2026-05-31）**

- `LibrarySearchBar`：默认折叠，仅显示搜索框 + 「筛选」按钮；展开后显示时间/大小/扩展名/标签高级面板。
- 折叠且存在高级筛选时，显示可点击移除的**摘要 chips**；按钮上显示激活数量 badge。
- 展开/收起使用 Grid 高度动画 + 内容淡入位移，并支持 `prefers-reduced-motion`。
- 切换分类/文件夹时通过 `filtersForCategoryChange` **保留搜索词**，重置扩展名、标签及时间/大小筛选。
- 辅助函数：`hasAdvancedFilters`、`getActiveFilterChips`、`removeFilterChip`（`libraryFilter.ts`）。

---

#### 2.2.4 列表视图增加列头排序（中）

**现状**：视频/音频分类有 `MediaSortBar`；文档、压缩包等普通列表仅按修改时间等前端默认排序，用户无法在表头点击排序。

**建议**：

- 为列表视图增加可选表头：名称、大小、修改时间、类型。
- 与现有 `MediaSortKey` 统一或扩展为 `ListSortKey`。
- 排序状态写入 localStorage，按分类记忆。

---

#### 2.2.5 设置页分区导航（低～中）

**现状**：`SettingsView` 单页长滚动，含资料库、规则、提醒、外观、更新等多块；找「外观」需大幅滚动。

**建议**：

- 左侧锚点导航或顶部 Tab：**资料库 | 规则与提醒 | 外观 | 关于与更新**。
- 各区块保持现有 `settings-panel` 样式，仅改信息架构。

---

#### 2.2.6 密度与布局偏好（低）

**现状**：已有主题色、强调色、字号三档；列表行高、缩略图尺寸固定。

**建议**（可选，设置 → 外观）：

- **紧凑 / 标准 / 宽松** 列表密度。
- 图片网格：**小 / 中 / 大** 缩略图（调整 `GRID_COL_MIN_PX` / `GRID_ROW_HEIGHT_PX`）。

---

### 2.3 交互与效率

#### 2.3.1 全局快捷键（中）

**现状**：仅 `FilePreviewModal` 监听 `Escape`；无应用级快捷键体系。

**建议**：

| 快捷键 | 行为 |
| ------ | ---- |
| `Ctrl+F` / `/` | 聚焦搜索框 |
| `Ctrl+A` | 当前列表全选（非输入框焦点时） |
| `Delete` | 删除选中项（弹出确认） |
| `F2` | 重命名选中项 |
| `Space` | 预览选中文件（Quick Look 风格） |
| `←` / `→` | 预览弹窗内上一张/下一张 |
| `Ctrl+R` | 刷新当前列表 |
| `Ctrl+1`～`9` | 切换侧栏常用分类（可选） |

- 在设置或「?」帮助面板中展示快捷键列表。

---

#### 2.3.2 右键上下文菜单（中）

**现状**：代码库中无 `contextmenu` / `onContextMenu` 实现；所有操作依赖行内按钮。

**建议**：

- 文件行、图片网格 cell、侧栏文件夹节点支持右键菜单。
- 菜单项与批量工具栏、行内操作对齐：打开、预览、收藏、标签、重命名、移动到…、还原、删除、在资源管理器中显示。
- 空白区域右键：新建文件夹、粘贴/收纳（若剪贴板有文件路径）、刷新。

---

#### 2.3.3 预览弹窗连续浏览（中）✅ 已完成

**现状**：`FilePreviewModal` 单文件预览，关闭后需回到列表再点下一个；图片分类浏览照片时效率低。

**建议**：

- 传入当前 `displayFiles` 与 `currentIndex`，支持上一项/下一项（按钮 + 键盘 ←/→）。
- 底部显示 `3 / 120` 计数；图片/PDF 可沿用现有 preview 组件。
- 视频预览切换时注意释放播放器资源。

**完成说明（2026-05-31）**

- `FilePreviewModal` 接收 `files`、`currentIndex`、`onNavigate`；左右导航按钮 + 键盘 `←` / `→`（`Esc` 关闭）。
- 底部显示 **`当前序号 / 列表总数`**；列表仅一项时隐藏导航。
- `LibraryView` 基于 `displayFiles` 计算索引，筛选导致当前文件不在列表时自动关闭预览。
- 切换文件时 `PreviewBody` 以 `key={file.path}` 重挂载；`VideoPreviewContent` 卸载时 `pause`、清除 `src` 并 `load()`。
- ⬜ **Space 快捷预览**（§2.3.1 全局快捷键）尚未做。

---

#### 2.3.4 图片网格交互增强（低～中）

**现状**：`ImageGridView` 已支持虚拟滚动、单击预览、双击打开、复选框多选；不支持框选、无幻灯片模式。

**建议**：

- **Shift+拖拽** 或鼠标框选批量选中（中）。
- 预览弹窗内「幻灯片播放」自动轮播（低）。
- 加载失败占位图提供「重试生成缩略图」按钮（低）。

---

#### 2.3.5 拖拽体验统一（低）✅ 已完成

**现状**：支持窗口内拖入收纳、库内拖到侧栏分类/文件夹；侧栏分类有 `nav-drop-target-active` 高亮。

**建议**：

- 外部拖入时在主区域显示更明显的 **全窗口 drop zone** 文案（当前 `drop-overlay` 仅在 `LibraryFileList` 内）。
- 拖入时预览将落入的目标分类（例如「将收纳到：图片」）。
- 库内多选文件后成组拖拽移动（中）。

**完成说明（2026-05-31）**

- 新增 `ExternalDropOverlay`（portal 至 `document.body`）：外部拖入时全窗口遮罩 + 动画，替代列表内 `drop-overlay`。
- `formatImportDropTargetLabel` + `resolveImportDropTarget`：实时显示「将收纳到：图片」「将放入：xxx」等目标文案。
- 库内多选成组拖拽：`setLibraryFileDragData` / `readLibraryFileDragPaths`；列表行与图片网格拖拽已选多项时一并移动；侧栏落点批量调用 `move_library_file_to_directory`。

---

#### 2.3.6 任务进度反馈合并（低）

**现状**：`LibraryFileList` 内 `task-progress-overlay` 可同时叠加列表加载、收纳、批量、错放整理等多个 `TaskProgressPanel`。

**建议**：

- 多个并行任务时合并为 **单一任务中心条**（可展开查看详情），避免多块进度条堆叠遮挡内容。
- 托盘收纳完成与窗口内 toast 已有分工，可在任务中心保留「最近 5 条任务历史」链接到操作日志。

---

### 2.4 空状态、引导与反馈

#### 2.4.1 强化空状态行动按钮（低）

**现状**：空资料库、空文件夹、无收藏等 empty-state 文案清晰，部分仅文字提示。

**建议**：

- 空资料库：增加 **「从桌面收纳」**、**「从下载收纳」** 两个 secondary 按钮，而不只依赖顶栏。
- 空收件箱：说明收件箱用途（若实现收件箱工作流，见 §3.1.1）。
- 筛选无结果：提供 **「清除筛选」** 一键按钮（搜索栏已有，空状态区可重复）。

---

#### 2.4.2 首次运行引导（中）

**建议**：

- 首次启动检测 `config.json` / 资料库是否为空，显示 3 步引导：① 确认资料库路径 ② 选择移动/复制 ③ 试收纳桌面。
- 可跳过；设置中提供「重新查看引导」。

---

#### 2.4.3 无障碍（中，持续）

**现状**：Modal 具备 `aria-modal`、`aria-label`；侧栏展开按钮有 `aria-expanded`；主文件列表缺少 roving tabindex 与键盘行导航。

**建议**：

- 列表行支持 ↑/↓ 移动焦点，Enter 打开，Space 预览。
- 批量工具栏与 `BatchToolbar` 的 checkbox 与 `aria-pressed` 保持一致。
- 焦点环在深色/浅色主题下均清晰可见（`:focus-visible` 审计）。

## 三、功能优化与补齐建议

### 3.1 收纳流程

#### 3.1.1 收件箱工作流（中）⭐✅ 已完成

**现状**：资料库有「收件箱」目录，收纳默认仍按扩展名直接进入各分类；`BatchMoveModal` 默认目标为「收件箱」，但无「先进收件箱再确认分类」的完整流程。

**建议**：

1. 设置项：**收纳目标** = 「直接分类」|「先进收件箱」。
2. 收件箱视图顶部显示 **「整理 N 个文件」** 按钮，调用现有错放整理/自动分类逻辑，将文件按规则分到各分类。
3. 侧栏收件箱 badge 显示待处理数量；处理完成后 toast「已整理 N 个文件」。

**价值**：降低误收纳焦虑，与产品设计文档一致。

---

#### 3.1.2 收纳后短时撤销（中）⭐

**现状**：收纳记录写入 `import_log.json`，需到「操作日志」页手动还原；无「刚刚收纳错了」的一键撤销。

**建议**：

- 收纳完成 toast 增加 **「撤销」** 按钮，5～30 秒内有效。
- 调用已有 `batch_restore` 或单条还原逻辑，按本次 task 涉及的 path 列表反操作。
- 超时后 toast 消失，仍可从操作日志还原。

---

#### 3.1.3 按大小 / 类型跳过收纳（低～中）✅ 已完成

**建议**：

- 设置：跳过小于 **N KB** 的文件（过滤临时缓存、空文件）。
- 桌面收纳：已有 `should_skip_desktop_file`，UI 上可展示「已跳过 N 个系统/快捷方式文件」摘要。
- 收纳确认弹窗 `ImportConfirmModal` 列出将跳过的文件及原因。

---

#### 3.1.4 总览扫描 → 一键收纳（中）⭐

**现状**：`OverviewView` 展示扩展名分布与子目录占用，与资料库收纳割裂；[功能规划建议.md](./功能规划建议.md) 标注为未完成。

**建议**：

- 扫描结果表格每行扩展名旁增加 **「收纳此类进资料库」**（从当前扫描目录筛选该扩展名文件）。
- 或顶部 **「将本文件夹可收纳文件移入资料库」**，弹出与桌面收纳相同的确认勾选 UI。
- 需明确：只收纳「资料库规则识别的类型」，并在 UI 说明将 **移动** 还是 **复制**。

---

### 3.2 浏览与搜索

#### 3.2.1 跨分类全局搜索（中）

**现状**：搜索在 `libraryFilter.ts` 前端过滤，范围限于**当前已加载列表**（当前分类或「全部」）；切换分类会 `setFilters(DEFAULT_LIBRARY_FILTERS)` 重置筛选。

**建议**：

- 侧栏增加 **「搜索全部资料库」** 模式，或搜索框旁 toggle：**当前分类 | 全部**。
- 长期：Rust 侧索引文件名（SQLite FTS），避免「全部」分类加载万级文件后再过滤。

---

#### 3.2.2 筛选状态记忆（低）

**建议**：

- 切换分类时保留 `query` 搜索词（用户常跨分类搜同名项目）。
- 扩展名/标签筛选按分类独立记忆（sessionStorage）。
- 「清除筛选」一键恢复默认。

---

#### 3.2.3 「最近添加 / 最近修改」视图（低～中）

**建议**：

- 侧栏或「全部」顶部 Tab：**全部 | 最近添加 | 最近修改**。
- 「最近添加」按 `import_log` 时间排序；「最近修改」按文件 `mtime`。
- 默认显示最近 7 天，可调整范围。

---

#### 3.2.4 文档列表缩略图（中）

**现状**：PDF 可在预览弹窗内嵌 `pdf.js`；列表行仅扩展名图标。

**建议**：

- PDF 第一页缩略图异步生成（类似 `thumbnail.rs`），缓存到 thumbnails 目录。
- Word/Excel 等仍用图标，避免 scope 膨胀。

---

### 3.3 整理工具

#### 3.3.1 总览 / 任意目录查重（中）⭐

**现状**：`DuplicateView` 仅扫描资料库内；总览扫描无查重入口。

**建议**：

- 总览页增加 **「查找重复文件」**，复用 `duplicate.rs`，对所选目录做大小预筛 + 哈希。
- 结果页区分 **「在资料库外」**：操作仅为「删除/打开/定位」，不提供「保留一份在资料库」逻辑。
- 与资料库查重共用 UI 组件，减少重复开发。

---

#### 3.3.2 查重结果增强（低～中）

**建议**：

- 按 **可释放空间** 排序重复组。
- 「智能保留」策略可选：保留路径最短 / 最新修改 / 已在收藏中的副本。
- 删除前预览：点击组内文件可打开预览弹窗比对（图片尤其有用）。

---

#### 3.3.3 操作日志增强（低～中）

**建议**：

- 按时间范围、分类、操作类型（收纳/还原/删除）筛选。
- 支持多选批量还原（已有后台任务，补 UI 即可）。
- 单条记录展示 **缩略图/图标** 提升可扫读性。

---

#### 3.3.4 批量打标签（低）

**现状**：批量工具栏支持移动、收藏、还原、删除；无批量编辑标签。

**建议**：选中多项后，「批量标签」弹窗：追加标签 / 替换全部 / 清除标签。

---

### 3.4 系统集成（功能向）

| 功能 | 现状 | 建议 | 难度 |
| ---- | ---- | ---- | ---- |
| 开机自启 | 托盘已有，设置无开关 | 设置 → 常规 → 开机自启（Tauri autostart 插件） | 低 |
| 资源管理器右键「收纳到 File Manager」 | 未做 | 安装时写注册表，卸载清理；参数传选中文件路径 | 高 |
| 拖拽到托盘图标收纳 | 未做 | 与窗口 drop 统一 `start_import_files_task` | 中 |
| 关闭窗口行为说明 | 默认最小化到托盘 | 设置中可选「关闭即退出」；首次关闭时 toast 提示 | 低 |
| 资料库备份提醒 | 未做 | 设置页提示定期备份；可选每月提醒 | 低 |

## 八、小结

v0.2.x 在「能收纳、能找、能整理」上已达标；下一步建议把力气花在：

1. **看得懂** — 侧栏数量、面包屑、首页概览，让用户知道资料库「有什么、待办什么」。
2. **点得少** — 收敛顶栏与行内按钮，补右键菜单与快捷键；预览连续浏览已完成，可补 Space 预览等。
3. **敢收纳** — 收件箱工作流、短时撤销、总览与收纳/查重打通，降低误操作成本。
4. **贴 Windows** — 开机自启、右键收纳、托盘拖拽、关闭行为可配置。

以上多数可复用现有 Rust 命令与 React 组件，无需推翻架构；优先实施第一批即可明显改善日常体验。

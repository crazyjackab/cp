# File Manager — 功能规划建议

> 基于当前版本（v0.2.0）已实现能力与 [产品设计.md](./产品设计.md) 中的目标整理。  
> 用于后续迭代排期，可按「价值 × 成本」选取实施。

## 一、当前已具备的能力

| 模块     | 功能                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 资料库   | 自动创建资料库及分类子目录；路径可在设置中修改并迁移                                                                                                                       |
| 收纳     | 自选文件、从桌面/下载收纳（确认勾选）、拖拽收纳；**移动 / 复制**可切换；同名冲突 **重命名 / 跳过 / 询问**                                                                  |
| 浏览     | 左侧分类导航、列表展示、**图片缩略图网格**、扩展名着色、**库内搜索与筛选**、**收藏**视图                                                                                   |
| 文件操作 | 打开、定位、还原、重命名、删除（回收站）；**单选/多选批量**删除、还原、移动分类                                                                                            |
| 元数据   | 自定义**标签**、**收藏**（`file_metadata.json`）；**错放分类整理**（预览 + 后台执行）                                                                                      |
| 工具     | **总览扫描**（任意目录占用统计，后台任务 + 进度/取消）                                                                                                                     |
| 查重     | **资料库内重复文件**：大小预筛 + 内容哈希分组；扫描与批量删除均为后台任务                                                                                                  |
| 日志     | **操作日志页**（`LogsView`）：读 `import_log.json`，跳转资料库/原路径、后台还原                                                                                            |
| 设置     | 外观、资料库路径/收纳模式、**扩展名→分类自定义**、**智能收纳提醒**阈值、自动更新                                                                                           |
| 系统集成 | **系统托盘**（打开、一键收纳桌面/下载、检查提醒）；收纳/迁移等 **Windows 通知**                                                                                            |
| 基础设施 | Tauri 2 打包、GitHub Release 自动更新；`config.json` / `import_log.json` / `file_metadata.json`；**统一 `background-task` 事件**（扫描、查重、收纳、列表加载、批量操作等） |

**仍待完善或仅部分实现的能力**（见下文各节标注）：收件箱收纳模式、总览目录查重入口、资源管理器右键收纳、操作撤销、视频/音频元数据增强等。

## 二、建议新增功能的总体思路

File Manager 的定位是 **「本机私人资料库」**，不是网盘、不是全盘清理大师。新增功能应优先满足：

1. **更快找到文件**（浏览、搜索、预览）
2. **更放心地收纳**（规则透明、可撤销、不误删）
3. **更少重复劳动**（规则、定时、批量）
4. **与 Windows 习惯衔接**（右键、托盘、通知）

下面按优先级与类别列出建议，并标注**预估难度**（低 / 中 / 高）。

---

## 三、高优先级（建议优先做）

这些功能与现有架构衔接紧、用户感知强，且多数在产品设计里已有提及。

### 3.1 库内搜索与筛选 ✅ 已完成

**做什么**

- 主界面顶部搜索框：按文件名模糊匹配当前分类或「全部」
- 可选筛选：修改时间范围、文件大小、扩展名多选

**价值**  
资料库文件一多，仅靠左侧分类不够；截图中已有 45+ 文件，搜索是刚需。

**难度**：低～中（前端过滤 + Rust 可选索引）

**实现说明（v0.1.x）**

- 资料库列表上方搜索栏：文件名模糊匹配
- 下拉筛选：修改时间（今天 / 7 天 / 30 天 / 一年）、文件大小（<1MB / 1–10MB / >10MB）
- 扩展名标签多选；切换左侧分类时自动重置筛选
- 前端即时过滤，无需 Rust 索引

---

### 3.2 图片分类：缩略图网格 ✅ 已完成

**做什么**

- 「图片」视图用网格展示缩略图（可先读本地缓存，异步生成）
- 单击预览大图或系统打开，双击打开默认程序

**价值**  
与「文档列表」形成差异化体验，符合「照片资料库」心智。

**难度**：中（Windows 缩略图 / `image` crate / 缓存目录）

**实现说明（v0.1.x）**

- Rust：`thumbnail.rs` 解码图片、生成 JPEG 缩略图，缓存至 `%APPDATA%\FileManager\thumbnails\`
- 前端：「图片」分类用 `ImageGridView` 网格展示；单击 `ImagePreviewModal` 预览大图，双击系统打开
- 不支持的格式（如 HEIC/RAW）显示占位图标，预览弹窗内可「打开 / 定位」

---

### 3.3 设置：资料库路径与收纳模式 ✅ 已完成

**做什么**

- 设置页可修改 `library_root`（迁移或新建提示）
- 收纳方式：**移动 / 复制** 可切换（写入 `config.json`）
- 展示收纳日志路径、一键打开资料库文件夹

**价值**  
配置能力已在 Rust 层存在（`config.rs`），只差 UI 与迁移引导。

**难度**：低～中

**实现说明（v0.1.x）**

- 设置页「资料库」区块：更改路径（迁移 / 仅切换）、移动·复制切换
- Rust：`set_library_root`、`set_import_mode`、`get_app_config`；收纳时按 `import_mode` 移动或复制
- 一键打开资料库、定位 `config.json` 与 `import_log.json`

---

### 3.4 收纳规则可配置 ⚠️ 部分完成

**做什么**

- 自定义扩展名 → 分类映射（覆盖默认规则）
- 可选：**收纳时跳过小于 N KB 的文件**、**跳过 `.lnk` 以外的系统文件**（桌面已部分实现）
- 「收件箱」模式：新文件先进收件箱，用户确认后再自动分到各分类

**价值**  
不同用户扩展名习惯不同；收件箱降低「误收纳」焦虑。

**难度**：中

**实现说明（v0.2.x）**

- ✅ 设置页可增删 **自定义扩展名 → 分类**（`set_custom_extension_rule`）
- ✅ 同名冲突策略、桌面收纳跳过规则（`should_skip_desktop_file`）
- ⬜ 按大小跳过、收件箱工作流尚未做

---

### 3.5 收纳历史 / 操作日志页 ✅ 已完成

**做什么**

- 读取 `%APPDATA%\FileManager\import_log.json`，展示最近收纳、还原、重命名记录
- 支持从日志跳转到资料库内文件或原路径（若仍存在）

**价值**  
后端已有 `import_log`，用户需要「我昨天收纳了什么」的可追溯感。

**难度**：低

**实现说明（v0.2.x）**

- 侧栏 **「操作日志」** → `LogsView`：`list_import_records`
- 展示名称、分类、大小、收纳时间、资料库/原路径是否存在
- 支持打开、定位、**后台还原**（`start_batch_restore_files_task`）

## 四、体验增强（中期）

### 4.1 文件预览 ✅ 已完成

| 类型 | 方案                                            |
| ---- | ----------------------------------------------- |
| 图片 | 应用内 lightbox 或侧边预览                      |
| PDF  | 内嵌预览（如 WebView + pdf.js）或仅第一页缩略图 |
| 视频 | 显示时长、分辨率；可选内嵌播放器                |
| 文本 | 只读预览前几 KB                                 |

**价值**：减少「打开 → 关闭 → 找下一个」的来回切换。  
**难度**：中～高（按类型分阶段做）

**实现说明（v0.2.x）**

- 统一 `FilePreviewModal`：图片 / PDF / 视频 / 文本
- 图片：沿用 data URL 大图预览；PDF：`pdf.js` 分页渲染；视频：HTML5 播放器 + 时长/分辨率；文本：Rust 读取前 32KB
- 列表可预览文件显示「预览」按钮；单击文件名也可预览（不可预览类型仍直接打开）

---

### 4.2 批量操作 ✅ 已完成

- 多选文件：批量删除、批量还原、批量移动到另一分类
- 全选 / 反选、Shift 连续选择

**价值**：整理大量下载文件时效率显著提升。  
**难度**：中

**实现说明（v0.2.x）**

- 列表与图片网格均支持复选框多选；Shift+点击连续选择
- 工具栏：全选、反选、批量删除 / 还原 / 移动到分类
- Rust：`start_batch_*_task` + `background-task` 事件（进度、取消）；查重页删除重复项亦走同一套批量删除任务

---

### 4.3 重复文件检测（查重） ✅ 已完成（资料库）

**做什么**

- 在资料库内按 **文件大小 + 哈希（可选）** 找重复
- 总览工具中增加「扫描目录并查重」入口
- 结果页：保留一份、其余删除或移出资料库

**价值**：产品设计 Phase 4 已规划；下载夹、资料库都常见重复安装包、重复图片。  
**难度**：中～高（大文件哈希耗时，需后台任务 + 进度条）

**实现说明（v0.2.x）**

- 侧栏 **「重复文件」** → `DuplicateView`；Rust：`duplicate.rs`（大小预筛 + SHA-256）
- `start_scan_library_duplicates_task`：后台扫描 + 进度/取消
- 按组选择「保留项」，其余 **批量删除至回收站**（后台 `start_batch_delete_library_files_task`）
- ⬜ **总览**任意目录查重入口、移出资料库（非删除）尚未做

---

### 4.4 智能收纳建议 ⚠️ 部分完成

**做什么**

- 启动时或定时检测：桌面/下载超过 N 个文件时，托盘或应用内提示「可收纳 X 个文件」
- 总览扫描结果页增加按钮：「将此类文件收纳进资料库」

**价值**：从「用户记得来收纳」变为「系统提醒收纳」，提高活跃度。  
**难度**：中

**实现说明（v0.2.x）**

- ✅ `smart_reminder.rs`：定时检测桌面/下载数量；超阈值 **系统通知**；设置页可开关与调阈值
- ✅ 托盘菜单：一键收纳桌面/下载（后台任务 + 完成通知）
- ⬜ 应用内总览页「一键收纳扫描结果」尚未做

---

### 4.5 视频 / 音频列表增强 ✅ 已完成

- 视频：显示时长、编码（`ffprobe` 可选）、按大小/日期排序
- 音频：艺术家/标题（有元数据时）、专辑封面

**难度**：中

**实现说明（v0.2.x）**

- Rust：`media_info.rs`（`symphonia` 探测时长/编码，`lofty` 读取音频标签与封面；若已安装 `ffprobe` 则作补充）
- 命令：`get_media_info` / `get_media_info_batch`
- 「视频」「音频」分类：列表显示时长、编码、分辨率（视频）；艺术家/标题、专辑、封面图（音频）
- 排序：修改时间、大小、时长（升/降）

---

### 4.6 标签与收藏（轻量） ✅ 已完成

- 用户给文件打自定义标签（存 JSON sidecar，不改文件名）
- 「收藏」星标，侧边栏「收藏」入口

**价值**：分类是物理目录；标签解决「跨类重要文件」场景。  
**难度**：中

**实现说明（v0.2.x）**

- 集中存储：`%APPDATA%\FileManager\file_metadata.json`（非每文件 sidecar）
- 列表/网格：收藏星标；`TagEditModal` 编辑标签；侧栏 **「收藏」** 筛选
- Rust：`set_file_favorite`、`set_file_tags`、`list_file_tags`

**难度**：低

## 九、不建议现阶段做的方向

避免偏离「私人资料库」定位：

- **全盘自动清理 / 注册表清理**：与竞品 CCleaner 等重叠，风险高
- **强制整理系统目录**：易误删，违背「用户显式收纳」原则
- **默认上传云端**：隐私与复杂度大增
- **社交/分享功能**：与核心场景无关

---

## 十、小结

当前版本（v0.2.x）已打通 **「收纳 → 分类存放 → 浏览管理 → 还原/删除」** 主链路，并补齐 **操作日志、资料库查重、标签/收藏、托盘与智能提醒、后台长任务（进度/取消）** 等能力。产品与代码已明显超前于早期「查重、日志未完成」的描述，路线图应以 **§八「下一批建议」** 为准。

后续仍可加强的方向：

1. **找得到** — 已有搜索/筛选/预览；可补排序、全文检索（长期）
2. **控得住** — 已有日志、冲突策略、自定义扩展名；可补收件箱、撤销
3. **用得勤** — 已有托盘与提醒；可补右键收纳、开机自启、总览一键收纳

在不推翻现有架构的前提下，继续贴近 [产品设计.md](./产品设计.md) 中的「私人资料库」愿景。
